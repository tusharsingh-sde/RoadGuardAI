1. PROJECT OVERVIEW
================================================================================
RoadGuard AI is a full-stack, AI-powered pothole detection and road-maintenance
cost estimation system. It uses a custom-trained YOLOv11 model to detect
potholes in real time from live camera feeds (IP/USB/drone cameras, device
browser cameras) or uploaded video files.

For every pothole detected, the system estimates physical dimensions (width,
breadth, depth) and calculates a maintenance repair cost in INR. At the end of
each detection session a branded PDF report is generated, uploaded to Supabase
Storage, and emailed to the administrator.

Authentication is handled via Supabase Auth with domain-restricted access
(configurable, defaults to @miet.ac.in), supporting Google OAuth and
email/password sign-in.

5. API SURFACE
================================================================================

WEBSOCKET ENDPOINTS (real-time streaming)
─────────────────────────────────────────

  ws://.../ws/drone-stream?email=user@example.com
    Model: PULL — backend connects to IP/USB camera, runs YOLO inference,
    streams annotated frames + detection data back over WebSocket.
    Client sends initial JSON: { "camera_url": "http://..." }
    Backend reads frames from OpenCV VideoCapture in a loop.

  ws://.../ws/device-stream?email=user@example.com
    Model: PUSH — client captures frames from device browser camera, sends
    base64-encoded frames as JSON: { "frame": "data:image/jpeg;base64,..." }
    Backend decodes, runs YOLO, returns annotated frame + detections.

  WebSocket Response Payload (both endpoints):
  {
    "session_id": "a1b2c3d4e5f6",
    "image": "data:image/jpeg;base64,...",
    "count": 3,
    "critical": 1,
    "high": 1,
    "medium": 1,
    "session_total_maintenance_cost": 1250,
    "session_unique_potholes": 5,
    "detections": [
      {
        "id": 1,
        "confidence": 0.91,
        "width_cm": 28.4,
        "breadth_cm": 19.2,
        "depth_cm": 8.7,
        "volume_m3": 0.00475,
        "estimated_cost": 190
      }
    ]
  }

REST ENDPOINTS
──────────────

  POST /api/v1/analyze-video?email=user@example.com
    Upload a video file (multipart form) for batch pothole analysis.
    Processes every Nth frame (N = FPS, i.e. 1 frame/second).
    Returns JSON with detection summary, per-pothole dimensions, costs.
    Triggers async PDF report generation + email in background thread.

  GET /api/v1/reports/{session_id}/status
    Poll the status of a session's PDF report.
    Returns: { "status": "processing" | "ready" | "error", "pdf_url": "...", ... }

6. CORE ALGORITHMS & BUSINESS LOGIC
================================================================================

POTHOLE DETECTION
─────────────────
  • Model: YOLOv11 custom-trained (pothole_best.pt), confidence threshold 60%.
  • Tracker: ByteTrack (bytetrack.yaml) for persistent IDs across frames.
  • Each unique track_id = one physical pothole (avoids double-counting).

DIMENSION ESTIMATION
────────────────────
  • CM_PER_PIXEL = 0.4 (configurable ratio)
  • Width  = (x2 - x1) × CM_PER_PIXEL
  • Breadth = (y2 - y1) × CM_PER_PIXEL
  • Depth  = 3.0 + (confidence²) × 15.0 + (area_px / 6000.0)
             clamped to [3.0, 25.0] cm

MAINTENANCE COST CALCULATION
─────────────────────────────
  Volume (m³)   = (width_cm / 100) × (breadth_cm / 100) × (depth_cm / 100)
  Material Cost = Volume × ₹8,500/m³
  Total Cost    = ₹150 (fixed labour) + Material Cost

SEVERITY CLASSIFICATION
───────────────────────
  • CRITICAL : confidence ≥ 85%
  • HIGH     : confidence ≥ 75%
  • MEDIUM   : confidence < 75%

7. AUTHENTICATION FLOW
================================================================================

Two-layer domain restriction for @miet.ac.in:

Layer 1 — Client-Side (UX only, not a security boundary):
  • AuthProvider.tsx evaluates every session via isAuthorizedEmail().
  • If domain doesn't match → immediate signOut + "unauthorized-domain" status.
  • Login page pre-validates email domain during sign-up.

Layer 2 — Database-Level (trusted security boundary):
  • PostgreSQL trigger on auth.users (restrict_email_domain.sql).
  • Fires BEFORE INSERT, raises exception for non-@miet.ac.in emails.
  • Blocks account creation for both Google OAuth and email/password.

Auth States: loading → signed-out | unauthorized-domain | authorized

Supported Methods:
  • Google OAuth (via Supabase signInWithOAuth)
  • Email/Password (sign-up with email confirmation + sign-in)

================================================================================
8. REPORT PIPELINE
================================================================================

  1. Session ends (WebSocket disconnect or video processing complete)
  2. Background thread spawned via threading.Thread (daemon=True)
  3. build_pdf_report() — generates branded A4 PDF with ReportLab:
     - Header with branding + timestamp
     - Summary stats (total potholes, total cost, source)
     - Per-pothole cards: cropped image, severity badge, dimensions, cost
  4. upload_pdf_to_supabase() — uploads PDF to "pothole-reports" bucket, gets public URL
  5. send_report_email() — sends rich HTML email with:
     - Styled summary (pothole count, maintenance cost)
     - CTA button linking to cloud PDF
     - PDF attached to email
  6. Report status tracked via in-memory dict + JSON file on disk
     Status values: "processing" → "ready" | "error"
